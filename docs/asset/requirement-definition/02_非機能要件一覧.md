## 1. 文書の目的

本件の非機能要件を性能・セキュリティ（認証／認可／監査ログ／暗号化／脆弱性の 5 観点）・可用性・拡張性・運用・移行・法令の観点で量化し、測定条件・対応設計文書・検証方法を対応付ける。

**測定規模の前提（真実性原則）**：本件は単一 Booking 環境（NestJS + Next.js + PostgreSQL + Redis の dev compose）× Salesforce 開発組織（chogeer DE org）× デモ規模データ（数十件）を対象とする。生産級の数字（大量データ・高並行・高可用率）は意図せず、デモ規模で実際に検証可能な値のみを設定する。

## 3. 補足

- 本表の数字はデモ規模の検証可能値であり、生産級 SLA ではない。生産展開時は再設定を要する（RD-07 の前提条件節に明記）。
- 可用性（NFR-10）は単一 org／単一環境であることを明示し、冗長化・フェイルオーバーは対象外とする。
- セキュリティは認証（NFR-04）・認可（NFR-05/06）・監査ログ（NFR-07）・暗号化（NFR-08）・脆弱性（NFR-09）の 5 観点に分割して管理する。
- 対応設計文書の注記：正式な引受先は非機能設計書（basic-design/nonfunctional-design.md）であり、同書が本表の非機能要件を引き受けて具体化する。面接資産（interview-portfolio-business-flow.md の MV アンカー）は設計文書ではなく検証観点の引用元として扱う。
