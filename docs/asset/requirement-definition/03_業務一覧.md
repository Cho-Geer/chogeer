## 1. 文書の目的と切り出し方針

本件の業務活動を「誰が・どんな契機で・何をする」の単位（一人が一回で完了する仕事の単位）で切り出し、要件（RD-01 REQ-xx）との双方向対応を確立する。

- 担当ロールの定義：**顧客**（Booking の CUSTOMER）、**管理者**（Booking の ADMIN／Salesforce 外部ユーザー。本件では同一人物が両方の認証情報を保有する前提）、**システム**（人手を介さず自動実行される処理）。
- 手動業務も列挙する（システム境界の根拠となるため）。
- 頻度・処理量は **デモ規模の実測見込み** であり、生産級の負荷想定ではない。

## 3. 手動業務の明示

| 業務 | 手動部分 | 理由（システム境界の根拠） |
|---|---|---|
| BIZ-15 | 409/FAILED の原因判断と Retry 実行の指示 | P0 は信頼性配信機構（Outbox/Worker）を持たないため、人手の判断を挟む設計（REQ-037＝P1 保留） |
| BIZ-16 | 月次の削除結果確認 | デモ運用では自動告警を設けないため、目視確認で担保 |
| （対象外業務） | SF 側からの改期・添付管理・全項目編集 | 本件スコープ外（RD-07 対象外）。必要時は管理者が Booking 管理画面（BIZ-04/BIZ-07）で手動対応 |
