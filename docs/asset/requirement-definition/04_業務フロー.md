## 1. 文書の目的と表記規約

業務一覧（RD-03）で切り出した業務（BIZ-01〜BIZ-16）をフロー図として可視化する。時系列の相互作用の詳細は『業務時序図』（docs/asset/requirement-definition-draft/interview-portfolio-business-sequence.md）を補助資料とし、本書はフロー（分岐・例外・差戻し）を主役とする。

- 泳道：`subgraph` で役割別に分割（顧客／Bookingシステム／管理者／Salesforce）。
- 開始・終了イベント：二重括弧 `(( ))` で表記。
- 分岐条件：分岐線上にラベル表記。
- 入出力帳票・データ：主要な I/O ノードには `IN:`（入力・受信データ）／`OUT:`（出力・送信データ）のラベルを付記し、対象（API ペイロード・メール・コマンドレコード・削除件数等）を明記する。帳票・データのやり取りがない UI 遷移のみの図（図 3・図 4）では付記しない。
- 点線枠：`style ... stroke-dasharray` = システム化範囲の境界（枠内が今回システム化対象）。
- 記載状態の注記：実装状態は図内ラベルに「既存実装」「P0-3 計画・未着手」等の文字表記で明記する（✅／🔵 等の記号は使用しない）。
- 記載内容の注記：計画中の図は設計目標であり、実装済みではない。

## 6. 図 5：予約投影（BIZ-12、Booking → Salesforce）

```mermaid
flowchart TB
    ST5(("開始：予約正本変更イベント<br/>（作成・変更・キャンセル全て）"))
    subgraph SYS5["Bookingシステム（BIZ-12・実装済み 2026-09-04・実機検証済み 2026-09-05）"]
        TX5["同一トランザクション更新：<br/>正本変更＋version+1＋syncStatus=PENDING（RULE-08）"]
        CALL5["OAuth 2.0 JWT Bearer で投影 REST 呼出（A2・REQ-029）<br/>OUT: 投影ペイロード（External ID・予約番号・日付・時間枠・サービス名・状態・version・eventId・correlationId／PII 除外：RULE-11）"]
        UPDS5["syncStatus=SYNCED 更新<br/>OUT: 同期完了の記録"]
        ERR5["syncStatus=ERROR 記録<br/>OUT: エラー記録（LastError）"]
        RETRY5["手動 Retry：同一 eventId で再送（BIZ-15 手順）"]
    end
    subgraph SF5["Salesforce（投影受入口・実装済み 2026-09-02・実機検証済み 2026-09-05）"]
        AUTH5{"サービス認証判定（A3 整合・誤認証は状態不変）"}
        VER5{"バージョン・イベント判定<br/>（RULE-01/04）"}
        UPSERT5["IN: 投影ペイロード受信<br/>External ID で Upsert：<br/>insert または update＋LastEventId/CurrentVersion 保存<br/>OUT: 受理結果（eventId・CurrentVersion）"]
        REJECT5["OUT: 拒否応答（旧バージョン・同バージョン別イベントの識別可能な応答）"]
    end
    EN5(("終了：投影反映"))

    ST5 --> TX5 --> CALL5 --> AUTH5
    AUTH5 -->|"認証 OK"| VER5
    AUTH5 -->|"401/403（認証 NG・予約/命令/投影状態は不変）"| ERR5
    VER5 -->|"初回イベント・より新しい version"| UPSERT5 --> UPDS5 --> EN5
    VER5 -->|"旧バージョン・同バージョン別イベント"| REJECT5 --> ERR5
    ERR5 --> RETRY5 --> CALL5

    style SF5 stroke-dasharray: 5 5
```

> 注：顧客自身の標準取消操作（BIZ-04）も同一の正本状態遷移を通り、本図の投影経路で同期される。差戻し（ERR5→RETRY5）は P0 の手順ベースの手動対応。

## 7. 図 6：予約キャンセルコマンド（BIZ-14、BIZ-15・Salesforce → Booking）

```mermaid
flowchart TB
    ST6(("開始：取消ボタン押下"))
    subgraph A6["管理者（Site・LWC）"]
        BTN6["投影リストで取消押下（BIZ-14）"]
        POLL6["コマンド状態ポーリング（IN: 状態問合せ／OUT: 状態取得）<br/>QUEUED→RUNNING→終状態"]
        DISP6["結果表示（CANCELLED）"]
    end
    subgraph SF6["Salesforce（連携資産 実装済み・P0-3/P0-4・実機検証済み 2026-09-05）"]
        PERM6{"権限・行級判定<br/>（RULE-13・OWD Private＋Sharing Set）"}
        MAKE6["Booking_Command__c 作成<br/>（commandId・expectedVersion・要求者）＋Queueable エンキュー<br/>OUT: コマンドレコード（監査項目付き）"]
        RESP6["commandId／QUEUED を即時返却"]
        QEU6["Queueable＋Named Credential で<br/>Booking 端点呼出（A3）<br/>OUT: コマンドリクエスト（CANCEL_BOOKING・commandId・expectedVersion・要求者）"]
        TERM6{"終状態書込判定<br/>（RULE-14：明示 200/409 のみ）"}
        RWRITE6["IN: 実行結果（canonicalVersion）<br/>バージョンゲート付き結果書き戻し（RULE-01・REQ-025）<br/>OUT: Booking__c 更新"]
        LOG6["エラー記録（終状態は書込まない）"]
        RT6{"リトライ上限内？"}
    end
    subgraph SYS6["Bookingシステム（実装済み 2026-09-03/09-04・実機検証済み 2026-09-05）"]
        IGUARD6{"Integration Guard<br/>（受信 Bearer token と env `INTEGRATION_TOKEN` の定数時間比較）"}
        IDEN6{"同一 commandId 判定（RULE-03）"}
        BIZCHK6{"業務判定（RULE-02/05/07/12：<br/>静的マッピング・ADMIN/ACTIVE・状態・expectedVersion）"}
        CANUPD6["IN: コマンドリクエスト<br/>同一トランザクション：<br/>正本 CANCELLED・version+1<br/>OUT: 200＋canonicalVersion＋resultCode"]
    end
    MAN6["手動対応（BIZ-15）：<br/>409 の原因確認・原 commandId で手動 Retry"]
    EN6(("終了"))

    ST6 --> BTN6 --> PERM6
    PERM6 -->|"許可"| MAKE6 --> RESP6 --> POLL6
    PERM6 -->|"拒否（終了）"| EN6
    RESP6 --> QEU6 --> IGUARD6
    IGUARD6 -->|"認証 OK"| IDEN6
    IGUARD6 -->|"401/403（状態不変・エラー記録）"| LOG6
    IDEN6 -->|"初回"| BIZCHK6
    IDEN6 -->|"重複：初回結果をそのまま返す（副作用なし）"| TERM6
    BIZCHK6 -->|"合法"| CANUPD6
    CANUPD6 -->|"200＋canonicalVersion＋resultCode"| TERM6
    BIZCHK6 -->|"409（業務競合・リトライしない：RULE-09）"| TERM6
    BIZCHK6 -->|"503/timeout（一時的障害・attemptCount+1）"| RT6
    RT6 -->|"上限内（同 commandId で再実行）"| QEU6
    RT6 -->|"上限超過"| TERM6
    TERM6 -->|"SUCCEEDED"| RWRITE6 --> DISP6
    TERM6 -->|"CONFLICT（409）"| MAN6
    TERM6 -->|"FAILED（リトライ上限超過）"| MAN6
    LOG6 --> MAN6
    MAN6 -->|"Retry 実行"| QEU6
    POLL6 --> DISP6
    DISP6 --> EN6
    style SF6 stroke-dasharray: 5 5
    style SYS6 stroke-dasharray: 5 5
```

> 注：409（CONFLICT）と 503（FAILED）の差戻し経路は本図の必須経路である。409 は自動リトライせず人間が判断（BIZ-15）、503 は同一 commandId で限定回数の自動リトライ。権限拒否（PERM6 の「拒否」）はコマンド生成前に終了する。
