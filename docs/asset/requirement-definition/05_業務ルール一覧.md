## 1. 文書の目的

業務の判定条件・制約をルールとして独立させ、機能設計（F-xx）とテストケースから直接引用できる形にする。各ルールは「可実行な表現（判定条件・例外・タイミングが明確）」で記述し、対応する MV 検証アンカー（docs/asset/requirement-definition-draft/interview-portfolio-business-flow.md）を備考に付す。

## 2. 業務ルール一覧

| ルールID | 対応業務ID | ルール内容（可実行な表現） | 適用タイミング | 例外条件 | 変更頻度 | パラメータ化要否 |

| RULE-01 | BIZ-12 | 投影受信時、`incomingVersion <= CurrentVersion__c` の場合は受理を拒否し、Booking__c を更新しない（可判定な競合応答を返す）。旧バージョン投影の遅延到達を上書きから防ぐ | 投影 REST 受信時（Apex・トランザクション内、External ID FOR UPDATE ロック後） | 初回登録（レコード未存在）は version 比較の対象外で insert を行う | 基本変更なし | 不要（プロトコル規約） |

| RULE-03 | BIZ-14 | 同一 `commandId` の再到達では、必ず初回保存済みの結果（HTTP 状態・canonicalVersion・resultCode）を返す。取消・通知等の副作用を再実行しない。HTTP タイムアウト後に正本更新が確定していた場合も同様 | Booking 統合端点受信時（業務判定より先行） | なし（冪等性は例外を許さない） | 基本変更なし | 不要 |
| RULE-04 | BIZ-12 | 同一 `eventId` の投影再送では、初回の受理結果をそのまま返し、レコードを追加更新しない（LastEventId__c で判定） | 投影 REST 受信時 | version が高い別 eventId は新規イベントとして処理する | 基本変更なし | 不要 |
| RULE-05 | BIZ-04, BIZ-14 | 予約状態の合法遷移は `PENDING→CONFIRMED`、`PENDING→CANCELLED`、`CONFIRMED→CANCELLED`、`CONFIRMED→COMPLETED` のみとする。`CANCELLED` と `COMPLETED` は終状態であり、いかなる遷移も不可 | 予約更新・取消・コマンド適用時 | なし（終状態の変更はデータ修正も含めて不許可） | 低 | 不要（状態遷移定義） |
| RULE-06 | BIZ-03 | 予約作成は、対象時間枠が稼働中かつ予約済みでない（実効容量=1、重複予約なし）場合のみ受理する。競合時は直列化＋限定回数リトライで解決する | 予約作成時 | 管理者が時間枠を停止した場合は空き照会から除外される（F-13） | 低 | 要（容量値。現在はハードコード値 1・P1 でマスタ化候補） |
| RULE-07 | BIZ-04, BIZ-14 | 取消は `PENDING` または `CONFIRMED` の予約のみ可能とする。`CANCELLED` への新 commandId 宛取消・`COMPLETED` への取消は 409 を返す | 取消実行時（顧客操作・コマンド共通） | なし | 基本変更なし | 不要 |
| RULE-08 | BIZ-12 | 予約正本の変更（作成・変更・キャンセルの全て—顧客自身の標準取消操作を含む）は、同一トランザクション内で正本更新＋`version` の +1 ＋`syncStatus=PENDING` を行う。version は単調増加とする | 正本変更トランザクション内 | version/syncStatus 未導入の既存機能（P0-2（契約凍結後）migration 前は本ルール非適用） | 基本変更なし | 不要 |
| RULE-09 | BIZ-14, BIZ-15 | エラーは 2 種に区分する。`409`＝業務競合：自動リトライせずコマンドを `CONFLICT` にする。`503/429/timeout`＝一時的障害：`attemptCount` を +1 し、同一 commandId で限定回数の自動リトライを行う | Queueable の応答処理時 | 401/403（認証エラー）は本区分の対象外：業務状態遷移・コマンド状態を変えずエラー記録のみ（RULE-14 注記・REQ-029）。※上限回数・間隔は 2026-09-02 確定（RULE-10 例外欄参照・CHK-02 C-5）。予期しない 500 等も一時的障害に準ずる | 低 | 確定（2026-09-02） |
| RULE-10 | BIZ-15 | 自動リトライ上限に達したコマンドは `FAILED`（AttemptCount／NextAttemptAt／LastError 記録）とし、以降の手動 Retry は原 commandId を用いて実行する（新規 commandId を発行しない） | リトライ上限到達時・手動 Retry 実行時 | なし | 低 | **上限回数＝2 回（初回含め総 3 試行）・間隔＝即時（Queueable 連鎖）・2026-09-02 確定（CHK-02 C-5）** |
| RULE-11 | BIZ-12 | 投影ホワイトリストは「予約 ID・番号・日付・時間枠・サービス・状態・version・同期管理項目」のみとし、顧客氏名・電話・メール・WeChat・備考（PII 5 項目）はペイロード・Booking__c のいずれにも含めない | 投影ペイロード生成時・Booking__c 項目設計時 | なし（例外の項目追加は P0-2 契約の凍結変更を要する） | 低（凍結後は変更管理対象） | 不要（ホワイトリストは契約凍結・2026-09-01 凍結） |
| RULE-12 | BIZ-10, BIZ-14 | 操作者の特定は Booking サーバ側の静的マッピング（`salesforceUserId ↔ bookingUserId`・active 1 件）のみで行う。ブラウザ申告のユーザー ID は採用しない。マッピング不存在／inactive、または対応 Booking ユーザーが現在 ADMIN かつ ACTIVE でない呼出は拒否する | 入口ボタン表示判定時・コマンド業務判定時 | なし | 低（P1 で動的 provisioning へ置換予定＝REQ-038） | 不要（P0 は事前登録レコード固定） |
| RULE-13 | BIZ-13, BIZ-14 | コマンド種別は `CANCEL_BOOKING` のみ受理する。Site 上の閲覧・送信は External OWD=Private＋Sharing Set（自 Account の行のみ）＋CRUD/FLS の範囲内に限定する（Apex は with sharing） | Site 操作時（照会・送信の各時点） | なし | 低 | 不要 |
| RULE-14 | BIZ-14 | Queueable が Booking_Command__c に終状態（SUCCEEDED/CONFLICT）を書込むのは、Booking から明示の `200` または `409` を受信した場合のみとする。401/403・timeout では終状態を書込まない | Queueable の応答処理時 | なし | 基本変更なし | 不要 |
