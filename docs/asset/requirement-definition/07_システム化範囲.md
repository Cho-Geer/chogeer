## 1. 対象業務

本件でシステム化する業務は、RD-03『業務一覧』のうち以下のとおり。

| 区分 | 対象業務 | 状態 |
|---|---|---|
| 顧客予約系 | BIZ-01〜BIZ-06（登録・ログイン・予約作成・変更取消・照会・通知） | 既存実装（Booking System） |
| 管理者系（Booking） | BIZ-07〜BIZ-09（予約管理・サービス／時間枠管理・ユーザー管理） | 既存実装（Booking System） |
| EC 連携系 | BIZ-10〜BIZ-15（入口利用・独立ログイン・予約投影・投影照会・取消コマンド・異常対応） | ログイン部分のみ検証済。投影・コマンド・LWC は P0-2〜P0-4 計画（未着手） |
| データ運用 | BIZ-16（30 日保持・ハードデリート） | 既存実装＋月次確認は手動 |

連携の中心は 1 本の縦断スライスである：「Booking 管理者ログイン → Experience Site 独立ログイン → 予約投影（Booking__c）閲覧 → CANCEL_BOOKING 送信 → Queueable＋Named Credential で Booking 呼出 → Booking が正本更新 → バージョンゲート付き投影書き戻し」。

## 2. 対象組織・拠点

| 対象 | 内容 | 備考 |
|---|---|---|
| Booking System | 単一テナントの予約システム（NestJS + Next.js + PostgreSQL + Redis）。dev compose で稼働 | 予約状態の正本 |
| Salesforce 開発組織 | chogeer DE org（Experience Cloud Site「my call center」/02・Live）。外部ユーザーは事前設定 1 名 | 本件の検証環境。生産 org は対象外 |
| 対象ユーザー群 | 顧客（CUSTOMER）数名・管理者（ADMIN）1 名（Salesforce 外部ユーザー認証情報と同一人物前提） | デモ・検証用の最小構成 |

## 3. 対象期間・データ量（デモ規模）

| 項目 | 設定 | 根拠 |
|---|---|---|
| データ保持期間 | 予約データは状態確定後 30 日でハードデリート（BIZ-16） | retention モジュール（既存実装） |
| 予約データ量 | 数十件（手動投入のデモデータ） | デモ・検証規模。性能目標もこの規模で設定（RD-02） |
| 投影レコード量 | 予約正本と 1:1 の数量（数十件以下） | 正本変更のたびに Upsert |
| コマンドレコード量 | 0〜数件（取消実行のたび） | デモ規模 |
| 移行データ | なし（新規構築・デモデータは手動投入） | RD-02 NFR-12 |

## 4. 対象外（今回実施しない事項・重点）

| No. | 対象外事項 | 理由 | 先送り先 |
|---|---|---|---|
| 1 | SSO／JIT／自己登録／自動ライセンスプール（REQ-034） | 本件の目的は予約連携の縦断スライスであり、認証統合は範囲外。独立ログイン（二次ログイン）を明示的に採用 | 対応しない（必要時に別案件） |
| 2 | Salesforce 内部ユーザー／System Administrator による連携（REQ-035） | 外部ライセンス＋最小権限の原則を守るため。内部ユーザーを使用すると権限検証の意味が損なわれる | 対応しない |
| 3 | 全項目自由双方向同期・改期・添付ファイル連携（REQ-036） | 「双方向」を「投影＋制限コマンド（CANCEL_BOOKING のみ）」に限定する。正本権威の原則を守るため SF 側編集は不可。Admin_Note__c は SF ローカル（P1 での表示） | 対応しない（P1 の Admin_Note__c 表示のみ） |
| 4 | Outbox／Worker／DLQ／周期照合・指標告警（REQ-037） | P0 は「直接呼出＋有限リトライ＋手動 Retry」で最小の縦断ループを構築。本番級の信頼性配信は工程・範囲の観点から後倒し | P1（保留） |
| 5 | 動的 provisioning／deprovisioning（SalesforceUserLink・Contact/User 生成・提権降権、sfAccessStatus 状態遷移）（REQ-038） | P0 は事前設定の外部ユーザー 1 名で足りる。設計は存在するが実装は後倒し | P1（保留） |
| 6 | Trigger／Batch／Email Service 等の追加 | 技術要素の追加を目的とした資産追加は行わない。Flow／標準 REST による代替も評価のうえ否決済み（tech-decisions 参照） | 対応しない |
| 7 | Exactly-once 配信・分散トランザクション・生産級高可用性・リアルタイム零遅延 | アーキテクチャの前提を超える品質目標。冪等（version＋commandId）による実質重複排除のみ提供 | 対応しない（本件スコープ外） |
| 8 | SF 側からの改期・予約作成 | コマンド種別は CANCEL_BOOKING のみ。改期が必要な場合は管理者が Booking 管理画面（BIZ-04）で手動対応 | 対応しない |
| 9 | Role 変更時の全デバイスセッション取消（RULE-17 の強化課題） | guard 化（booking-backend 9040902）により JWT role≠DB role の旧トークンは拒否（2026-09-03 実装実態反映）。DB セッション行の失活は後工程 | P1（強化項目） |

## 5. 外部システム連携範囲

| 方向 | 連携内容 | 範囲・程度 | 認証 |
|---|---|---|---|
| Booking → Salesforce | 予約投影（作成・変更・キャンセル全ての正本変更） | Booking__c への冪等 Upsert（External ID 定位・version ゲート・eventId 再送対応）。項目はホワイトリスト（PII 除外）。P0 はサービスからの直接呼出 | OAuth 2.0 JWT Bearer（外部クライアントアプリケーション ECA・A2） |
| Salesforce → Booking | 取消コマンド（CANCEL_BOOKING のみ） | Booking_Command__c 生成 → Queueable＋Named Credential で Booking 統合端点呼出。Booking 側で静的マッピング・ADMIN/ACTIVE・状態・expectedVersion を検証し、同一トランザクションで正本更新。409／503 を区分し、503 は限定回数リトライ＋手動 Retry | Named Credential（静的 Bearer Token・カスタムヘッダー注入〔EC 認証パラメータ `guardSecret`（既存・新規追加なし）・NC 数式許可 ON〕）＋Integration Guard（定数時間比較・A3） |
| Salesforce → Booking（結果） | コマンド結果の書き戻し | バージョンゲート付きで Booking__c に canonical result を反映（incomingVersion が高い場合のみ） | （上記 Queueable 内） |
| 対象外の連携 | 改期・添付・全項目同期・イベント駆動のリアルタイム配信 | 実施しない（§4 参照） | — |

連携の責任分界：予約状態の最終値は常に Booking のトランザクションが決定する。Salesforce は投影の表示とコマンドの受理のみを担い、正本を直接書き換えない。

## 6. 前提条件・制約

1. Salesforce 側：Network が Live であること（P0-1 済）、事前設定の外部ユーザー 1 名がログイン可能であること（MV-03 済・ログイン部分）。
2. Booking 側：P0-3 で HTTP クライアント・OAuth 依存を新規導入する（現在はゼロ）。`version`／`syncStatus` は P0-2 契約凍結後に migration で追加する（13 モデル現状なし）。
3. External ID の二択（`appointmentNumber` vs uuid `id`）は 2026-09-01 に uuid `id` と決定済み（TERM-14・DD-01 §5 未決 1 参照）。両方を同時に External ID にはしない。
4. Named Credential の目標 URL は Booking の稼働環境（本機 dev compose か booking-deploy か）確定後に設定する（G3）。→【確定済 2026-09-02】booking-deploy 公網 HTTPS に最終指向（CHK-02 C-1・S-2 仮値許容・P0-4 実リンク検証前にデプロイ・切替）。
5. 連携資格の前提：コマンド操作者は「Booking の現在 ADMIN かつ ACTIVE」かつ「静的マッピング active」であること（RULE-12）。
6. 品質目標はデモ規模（RD-02）であり、生産級 SLA・可用性率・大量データは前提としない。前提が崩れる（生産展開する）場合は本範囲を再協議する。
